# Local integration of PR #224, #214, #211 — 2026-10-17

Changes were adapted to the current local fixes. Nothing was sent to GitHub.
Validation used RX 7800 XT / RADV; NVIDIA was not tested.

## Changes

- [#224](https://github.com/deadinside28/bloodborne_pc/pull/224): the two GX command
  heaps increased from 256 KiB to 1 MiB. Enabled by default; `BB_GX_COMMAND_HEAP=0`
  disables it. These are separate buffers, not Laurence's resource cache previously
  enlarged to 512 MiB.
- [#214](https://github.com/deadinside28/bloodborne_pc/pull/214): common hooks also
  install in Old. GPU-cache notification, allocation, copy and collector hooks require
  New. Local loading, cinematic and widescreen fixes were preserved.
- [#211](https://github.com/deadinside28/bloodborne_pc/pull/211): swapchain recreation
  during resize, reacquire and HDR changes is protected by a common submit_mutex.
  Setting the same HDR again does not recreate the swapchain.

## Checks

- GPU-library and AppImage builds successful.
- 130 Python tests passed, including checking the exact two #224 patch writes.
- Native fx-init-clear, cp-decoder, ui-composition, srt-walker-fault and settings
  tests passed. The fault test deliberately causes read faults; these are not
  game-launch failures.
- Patch on/off and both 1-MiB operands in game memory checked.
- Old: source launch, save load, about 95 seconds after loading began, window-resize
  checks. No Bad PM4, SRT walker, Job allocation or Device Lost errors.
- New: Vulkan Validation layer actually loaded. Resize checks performed in a repeat
  launch; no threading validation, Bad PM4, Job allocation or Device Lost errors.
  The user manually closed New windows after the 60-second mark; completion of the
  entire cinematic in those runs is not confirmed.

The performance drop in the last test window occurred with Vulkan Validation enabled:
last frame median 27.46 ms (about 36 FPS). In Old without validation, a typical median
was 10.02 ms (about 100 FPS). These are different conditions, so the results are not
an Old/New performance comparison or evidence of a regression from these changes.
The user confirmed the slowdown was specifically in the last test window.
Normal launcher settings have `vk_validation=false`; it was enabled only in a separate
test profile. No background game processes remain after testing. At the user's request,
window position, size and fullscreen control were removed from the test script;
no additional game launches were performed for this report.

Validation materials: `out/dev/pr224-214-211/`, including logs, memory states,
screenshots, original versions of changed files and `implementation.diff`.
