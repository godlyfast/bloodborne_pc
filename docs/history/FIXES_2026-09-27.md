## 1. Reactive mask is not saved ✅ FIXED

### Problem
The "Show mask (debug)" checkbox in the menu worked, but the `debug_view` setting was not saved to `bbport.ini`, so after a restart the mask was not displayed.

### Cause
In `bbport_settings.cpp`:
- The `Set()` function did not handle the `debug_view` key
- The `Save()` function did not write the `debug_view` value to the file

### Fix
**File:** `native_probe/gpu/shim/bbport_settings.cpp`

1. Added handling in `Set()`:
```cpp
} else if (key == "debug_view") {
    v.debug_view = std::clamp(i, 0, DebugViewCount - 1);
}
```

2. Added writing in `Save()`:
```cpp
"debug_view=%d\nshow_fps=%d\n",
// ...
v.debug_view.load(), int(v.show_fps.load())
```

### How to verify
1. Launch the game
2. Open the menu (Insert or L3+R3)
3. Enable "Reactive mask" → "Show mask (debug)"
4. Close the menu
5. The mask should be displayed in red over the darkened frame

## 2. Weapon trails

### Analysis
The logs show:
```
Object motion: on (4194304 vertices per frame)
```

Object motion vectors are enabled and working. The trails may be caused by:

#### Possible causes:

**A. FSR 3.1 problem**
- FSR 3.1 may handle fast-moving objects incorrectly
- Need to compare with FSR 4 (when implemented)

**B. Object motion vectors are inaccurate**
- The selective path enables vectors only for draws with pose/bone buffers
- The weapon on the back may use a different animation type

**C. Reactive mask does not work for the weapon**
- The mask only marks transparent effects (particles, haze)
- The weapon is an opaque object, so the mask does not affect it

**D. Jitter is disabled**
From `bbport.ini`:
```
jitter=0
```
Subpixel offset is **disabled**, which degrades temporal upscaler quality!

### Testing recommendations

1. **Enable jitter:**
   ```ini
   jitter=1
   ```
   Jitter is critically important for FSR 3.1!

2. **Check the reactive mask:**
   - Enable `debug_view=1` and `reactive=1`
   - See which areas are marked as reactive
   - The weapon should NOT be in the mask (it is opaque)

3. **Try increasing reactive_scale:**
   ```ini
   reactive_scale=2.00
   ```
   (although this is for transparency, not for the weapon)

4. **Disable object vectors for comparison:**
   ```ini
   object_motion=0
   ```
   Restart and compare — does it get worse or better?

5. **Try different presets:**
   - Native AA (preset=0) — no scaling
   - Quality (preset=1) — x1.5
   - Performance (preset=3) — x2.0
   
   Trails should be smaller at higher render resolutions.

### Debug logs

Enable motion vector debugging:
```bash
BB_DEBUG_MOTION=1 ./run.sh
```

These options should appear:
- Toggle 1<<22: previous-frame reprojection
- Toggle 1<<23: error map

## 3. Restart required to apply settings

### Current situation

From the logs:
```
GPU scene scaling: AMD Radeon RX 7800 XT (RADV NAVI32) lacks blit support for D32S8
GPU scene scaling: using startup resolution 960x540 for this driver
```

Your RX 7800 XT **does not support blit D32S8** (copying the depth+stencil buffer), so the old path is used:
- Resolution is set by a patch at startup
- Changing the preset requires a restart

### New path (in the working tree, not committed)

According to ROADMAP.md, the working tree contains code for:
- Dynamic renderer-level scaling
- Preset switching without a restart
- Automatic fallback for GPUs without blit D32S8

But this code is **not committed yet** — the author is waiting for testing on a real GPU.

### What works without a restart

These settings apply **immediately**:
- ✅ Upscaler on/off
- ✅ Sharpness
- ✅ Jitter (unless BB_LIVE_SCALING_UNSUPPORTED is set)
- ✅ Reactive mask and its parameters
- ✅ Debug modes

### What requires a restart

On your GPU:
- ❌ Preset change (Native AA ↔ Quality ↔ Performance)
- ❌ Object motion vectors on/off

### Workaround

To test different presets without restarting the game:
```bash
# Edit bbport.ini
preset=1  # Quality
# Restart only the process (Ctrl+C, then ./run.sh)
```
