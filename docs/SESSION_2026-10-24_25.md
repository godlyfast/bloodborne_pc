## Done

### Performance
- **PGO silently did not work** since the project moved to `bbport/`: the profile was at the old path and the build hid the warning. The releases of recent weeks shipped without PGO.
  - Profile file names are now relative (`-fprofile-prefix-path`).
  - `build.sh` warns about a foreign profile and builds without it.
  - The profile was recorded again. It has to be re-recorded before a release: the code has changed since.
- **Sorting in the game's copy shader** (~130 calls per frame) took 6% of the draw recording thread. I replaced it with a cache and merging of already sorted runs; it is now 2%.
- **`NewestGpuWrite`:** a fast per-page check instead of dozens of hash table accesses.
- **Barriers:** a fast path for the reflection cube array, which is bound in parts.
- **Constants synchronization:**
  - the constants dump (`DumpConstRam`) no longer waits for the GPU because of CPU tasks;
  - it waits for the GPU only where stage B actually bound the data in place (`BufferCache::in_place_read_hook`).
  - Deck: GPU wait ~70 → 1–3 ms/s.
- **Windows build:** PGO (Clang) and LTO were added (`WIN_PGO`, `WIN_LTO` in `package.sh`). No gain on the laptop; both are off by default.

### Bugs found in your game on the Deck
- **Sewers: shimmer and a frame-rate drop.** The reactive mask took the 320×200 fog buffer instead of the 640×400 scene. Because of this the upscaler resources were recreated twice per frame and the FSR history was reset. Now the mask skips such a frame.
  - Remaining: teach the mask to take the correct buffer.
- **Black spots on the ground and a missing reflection.** The cause is heap shrinking (returning memory chunks after loads). Shrinking is **off by default** (`BB_HEAP_SHRINK=1` turns it on).
  - The root cause has not been found. Suspicion: data written by the GPU into a chunk after it was handed out again goes to the wrong place.
- **Yahar'gul on the PC: 105 FPS.** Yesterday's mirror changes delayed moving new data into VRAM, and the GPU read it over the bus. Both changes are **off by default** (`BB_MIRROR_REPROMOTE_SECONDS`, `BB_MIRROR_UNBOUND_SECONDS`).

### ReBAR
- A measurement confirmed that the CPU hardly touches the game's graphics heaps (3.2 GB).
- But moving the heaps directly into VRAM (`BB_GUEST_VRAM=graphics`) gives **9–18 FPS**. The cause is that our own code reads these heaps from the CPU:
  - object motion vectors;
  - constants copying;
  - lookup of a ready pipeline by shader code.
- For ReBAR to work, these reads have to be moved to the GPU or into a cache. A large separate task, postponed.

## Where we stopped

1. **Texture preloading** — your item 3 on the frame-rate drops at transitions between locations. This is in progress.
   - **Done:**
     - interception of `Texture::initAs2d` from libGnm with a filter on the game's graphics framework;
     - textures are created in advance, at most 24 MB per frame;
     - the crash from garbage descriptors is fixed.
   - **Not working:** the textures created in advance are then not found in the cache. Either the draw binds a single mip level while the loader describes all of them, or these are render targets, not textures. The spike on entering the world did not shrink.
   - **Next step:** exclude render targets and teach the cache to return a texture created in advance as a view of the needed mip.
2. **Uneven frame time on the laptop.** Frames come in "long–short" pairs. Without the two-stage pipeline everything is even, but at 14 FPS. Runs with the mirror fix and with a 28 FPS limiter are in progress now.
3. **Heap shrinking:** find the root cause of the data corruption and bring back the memory savings.
4. **Reactive mask** in places with fog.
